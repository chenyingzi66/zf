## 4. 请求层改造(`src/api/http.ts`)

以模版 `src/api/adapters/http.ts`(205 行)为底稿,逐条改:

| # | 模版行为 | 出处 | 改成 |
|---|---|---|---|
| 1 | `baseUrl` 默认 `http://localhost:8989` | `http.ts:4-5` | 默认 `http://localhost:8080`,仍读 `VITE_API_BASE_URL`,保留去尾斜杠 |
| 2 | 路径都带 `/api` 前缀 | `http.ts:126-203` | 全部去掉前缀,直接写 `/admin/login` 这类真实路径 |
| 3 | 成功判定 `code === 0` | `http.ts:93` | 改成 **`code === 200`**,其余抛 `Error(message)` |
| 4 | 信封识别 `'data' in body && ('code' in body \|\| 'message' in body)` | `http.ts:39` | 改成 **`'code' in body`**。后端 `data` 为 null 时字段会消失,原判据会把 `{code:200,message:"success"}` 当裸数据返回 |
| 5 | 靠 HTTP 401 触发刷新/登出 | `http.ts:76-88` | 后端 HTTP 永远 200,改成**看 `body.code === 401`** |
| 6 | `/api/auth/refresh` 单飞刷新 | `http.ts:49-66` | **整段删除**,后端没有该接口。401 → 清 token → 派发 `ao-auth-required` 事件(`App.tsx:148-158` 已监听并跳 `/login`) |
| 7 | token key `manga_workshop_tokens` | `http.ts:10` | 改 `zf_admin_token`。只存 `accessToken`(后端不发 refreshToken) |
| 8 | 上传字段名 `files` + `folder` | `http.ts:173-178` | 改成单文件字段名 **`file`**,无 folder |
| 9 | 上传响应按对象解析 | — | 后端 `data` 是 **URL 字符串**,直接当 string 用 |
| 10 | REST 动词 PUT/DELETE | `http.ts:131-132` 等 | 全改 POST;路径参数式删除要 `POST` + **空 JSON body `{}`** |
| 11 | 网络异常文案 | `http.ts:74` | 保留「无法连接后端服务,请确认服务已启动」,很实用 |

对外暴露三个薄封装即可:

```ts
get<T>(path)                     // GET,无参
post<T>(path, body?)             // POST + JSON,body 默认 {}
upload(path, file)               // POST + FormData(字段名 file),返回 string
```

`Authorization: Bearer <token>` 照常带上。后端目前把 `/admin/**` 整段排除、不校验 token(见对接文档 §1.3),带上是为了将来后端补校验时前端不用改 —— **不能因此认为管理端是受保护的**。

## 9. Docker 与运行

**关键约束:Vite 7 要求 Node ≥ 20.19(或 ≥22.12),现有 `admin/Dockerfile.dev` 是 `node:18-alpine`,直接跑不起来。**

新增 `admin-pro/Dockerfile.dev`:

```dockerfile
FROM node:22-alpine
WORKDIR /app
EXPOSE 5174
CMD ["npm", "run", "dev", "--", "--host", "0.0.0.0"]
```

`docker-compose.dev.yml` 追加服务(**旧 admin 服务完全不动,两个界面并行对照**):

```yaml
  admin-pro:
    build:
      context: ./admin-pro
      dockerfile: Dockerfile.dev
    container_name: suixinzhu-admin-pro-dev
    restart: unless-stopped
    working_dir: /app
    ports:
      - "${ADMIN_PRO_PORT:-3003}:5174"
    environment:
      VITE_API_BASE_URL: http://localhost:8080
      TZ: Asia/Shanghai
    volumes:
      - ./admin-pro:/app
      - suixinzhu_admin_pro_modules:/app/node_modules   # 匿名卷防止宿主目录覆盖依赖
    command: sh -c "npm install && npm run dev -- --host 0.0.0.0"
```

三个要点:

1. `VITE_API_BASE_URL` 必须是**浏览器视角**的地址(`http://localhost:8080`),不能写容器名 `backend` —— 请求是浏览器发的,不是容器发的。
2. `/app/node_modules` 必须挂命名卷或匿名卷,否则宿主的 `admin-pro/` 目录会把容器内装好的依赖盖掉。
3. 启动命令带 `npm install` 是为了首次自动装依赖;依赖没变时 npm 会秒过。

启动:

```bash
export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"
cd /Users/code/km/zf
MYSQL_PORT=3307 ADMIN_PORT=3002 ADMIN_PRO_PORT=3003 docker compose -f docker-compose.dev.yml up -d --build admin-pro
```

访问 http://localhost:3003(新界面)、http://localhost:3002(旧界面对照)、http://localhost:8080(API)。

本地不走容器时:`cd admin-pro && npm install && npm run dev`,默认 5174。`.env.local` 里写 `VITE_API_BASE_URL=http://localhost:8080`。

## 12. 风险与回滚

| 风险 | 处理 |
|---|---|
| 宿主 Node < 20.19 | S0 就会暴露。选项:nvm 装 22,或只在容器里开发(改代码仍热更新) |

| 依赖装不上 | 模版 `.npmrc` 锁了 npmmirror 源(国内更快),保留;若在境外网络反而失败,临时 `npm i --registry=https://registry.npmjs.org` |
| 模版 `tsconfig` 是 `strict: false`、ESLint 关了 `no-unused-vars` | 沿用,不在本次重构里折腾配置 |
| 单 chunk 打包(模版无代码分割) | 我们只有 9 个页面,无需 `React.lazy` |
| 新界面出问题 | 旧 `zf/admin` 完整保留且仍在 3002 上跑,随时切回;`admin-pro` 是独立目录,删掉即回滚 |
