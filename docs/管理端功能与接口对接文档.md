## 1. 全局约定

### 1.1 基础地址

| 项 | 值 | 出处 |
|---|---|---|
| 后端地址 | `http://localhost:8080` | `admin/js/admin.js:4` |
| context-path | `/`,**没有 `/api` 前缀** | `backend/src/main/resources/application.yml:1-4` |
| 旧管理端地址 | 容器内 3001,宿主当前映射 3002 | `admin/server.js:5`、`docker-compose.dev.yml:60` |
| 静态图片 | `http://localhost:8080/uploads/**` | `WebMvcConfig.java:56-59` |

CORS 已放开:`CorsConfig.java:11-21` 用 `addAllowedOriginPattern("*")` + 全部方法/头 + `allowCredentials(true)`,新前端换任何端口都不需要改后端。

### 1.2 响应信封

所有接口统一返回 `Result`(`common/Result.java:9-75`):

```json
{ "code": 200, "message": "success", "data": ... }
```

| 规则 | 说明 | 出处 |
|---|---|---|
| **成功码是 200** | 不是 0。前端一律 `res.code === 200` 判定 | `Result.java:17-44`、`admin.js:115,202` |
| 业务失败码是 **400** | `Result.error(msg)` 默认 400,占绝大多数错误 | `Result.java:48` |
| 未登录码是 **401** | 只有拦截器会产生 | `AuthInterceptor.java:27-30` |
| 系统异常码是 **500** | 未捕获异常,文案固定「系统繁忙,请稍后重试」 | `GlobalExceptionHandler.java:13-44` |
| **HTTP 状态永远 200** | 连 401/500 也是 HTTP 200,`AuthInterceptor.java:48` 显式 `setStatus(200)` | 同上 |
| **`data` 可能整个消失** | `@JsonInclude(NON_NULL)`,`data` 为 null 时该字段不出现在 JSON 里 | `Result.java:9` |

> 对接要点:判定成功**只能看 `body.code`**,不能看 HTTP 状态;判定「是不是信封」**不能靠 `'data' in body`**,要靠 `'code' in body`。模版自带的请求层两条都踩了(`ao-admin-pro/src/api/adapters/http.ts:39,93` 用 `'data' in body` + `code === 0`),必须改。

### 1.3 认证现状(重要,重构时别按常规后台的假设写)

| 事实 | 出处 |
|---|---|
| `POST /admin/login` 会返回真 JWT(`role=ADMIN`,7 天过期) | `AdminController.java:53-59`、`JwtUtils.java:33-46` |
| 但**现有界面把 token 丢了**,只读 `data.username` | `admin.js:115-119` |
| 现有登录态 = `localStorage['admin_logged'] === '1'` 一个字符串 | `admin.js:118,503` |
| 现有请求**不带任何 `Authorization` 头** | `admin.js:6-14,16-28` |
| 拦截器把 `/admin/**` 整段排除,所以带不带 token 都能调通 | `WebMvcConfig.java:19-52` |
| 管理端用到的非 `/admin` 路径(`/house/all`、`/house/audit`、`/house/delete/**`、`/feedback/*`、`/order/delete/**`、`/banner/*`、`/upload/**`)也全部在排除名单里 | 同上 |
| 账号硬编码 `admin`,密码是**静态内存字段**(初始 MD5(`123456`)) | `AdminController.java:38,45,49` |
| 改密码只改那个静态字段,**重启即失效**,`sys_admin` 表从头到尾没被读写 | `AdminController.java:87`、`database/suixinzhu.sql:39-49` |

安全结论(如实记录,本次不改):任何能访问 8080 的人都能删用户、删房源、删订单、改审核状态。新前端会把 token 存下来并在请求头带上(向前兼容,后端将来加校验就不用改前端),但**不能声称这样就安全了** —— 真正的修复必须在后端做。

### 1.4 分页现状

**后端全站没有分页。** 全仓库 `.java` 里 `pageNum`/`pageSize`/`IPage`/`PaginationInnerInterceptor` 零命中,`common/PageResult.java:12-15` 定义了却没人用。所有列表接口一次性返回全表。

现有界面也没有分页:`共 N 条记录` 直接取 `list.length`(`index.html:300,340,383,442,485`),房源筛选是内存过滤(`admin.js:90-102`)。

> 对接要点:新前端沿用「一次拉全量 + 前端内存分页/过滤/排序」。模版的 `UsersPage` 也是这个套路(`listUsers({pageSize:100})` 后本地切片),不冲突。

### 1.5 时间格式

| 类型 | 实际序列化 | 说明 |
|---|---|---|
| `LocalDateTime`(`createTime`/`updateTime` 等) | `"2026-09-03T10:08:54"` | **带 `T`**,无时区偏移 |
| `LocalDate`(`checkInDate`/`checkOutDate`) | `"2026-09-03"` | 纯日期 |

`application.yml:28-29` 的 `date-format: yyyy-MM-dd HH:mm:ss` 只作用于 `java.util.Date`,而本项目全用 `java.time`,且实体上**没有任何 `@JsonFormat`** —— 所以生效的是 ISO 格式。现有前端靠字符串手术处理:`admin.js:497-500` 的 `dateStr.replace('T',' ').substring(0,19)`。

> 对接要点:新前端写一个 `formatDateTime` 工具,兼容带 `T` 和不带 `T` 两种输入,空值回落 `-`(与现有界面一致)。

### 3.1 需要特别注意的几条

**#1 登录**:失败统一返回 `{code:400, message:"用户名或密码错误"}`。`username` 必须严格等于 `admin`。

## 5. 重复接口:现有界面用的是哪一套

后端存在四组功能重复的接口,现有界面混着用。**1:1 重构必须沿用左边这一列**,否则行为会有细微差别。

| 功能 | 现有界面用的 | 另一套(本次不用) | 差别 |
|---|---|---|---|
| 房源列表 | `GET /house/all` | `GET /admin/house/list` | 无差别,都是全表 |
| 房源审核 | `POST /house/audit` | `POST /admin/house/audit` | 级联逻辑完全相同(`HouseServiceImpl.java:142-146` vs `AdminController.java:198-202`) |
| 订单列表 | `GET /admin/order/list` | `GET /order/all` | `/order/all` **需要 token** 且按 `createTime DESC` 排序;`/admin/order/list` 免 token 但不排序 |

## 6. 坑清单(重构时逐条对照,防止踩)

1. **成功码 200 不是 0。** 模版请求层默认 `code === 0`,必须改。
2. **`data` 可能不存在**(`@JsonInclude(NON_NULL)`)。信封识别要用 `'code' in body`,不能用 `'data' in body`,否则 `Result.success()`(只有 code+message)会被当成裸数据返回。
3. **HTTP 状态永远 200**,401 也是。登出跳转要判 `body.code === 401`。
4. **后端没有 refresh token 接口**,模版请求层里的 `/api/auth/refresh` 单飞刷新逻辑要整段删掉,401 直接清 token + 跳登录。
5. **所有写操作都是 POST**,包括删除。路径参数式删除要带空 JSON body。
6. **路径没有 `/api` 前缀**,模版所有路径都是 `/api/xxx`,要全部改写。
7. **上传字段名是 `file`(单数)**,模版是 `files`(复数,支持多选)。轮播图是单图上传。
8. **上传响应是字符串**,不是 `{url}` 对象。
9. **图片地址是后端拼的绝对地址**(带 `http://localhost:8080`)。换主机名/端口后历史数据里的地址会全挂。新前端加一个 `normalizeImageUrl`,把 host 部分按 `VITE_API_BASE_URL` 重写,规避这个问题。
10. **时间带 `T`**,`formatDateTime` 要处理;`checkInDate`/`checkOutDate` 是纯日期,不能套同一个格式化函数。
11. **列表接口返回 `password`**,禁止渲染、禁止打日志、禁止进 CSV 导出。
12. **三套删除 key**(`houseId` / `orderNo` / 数字 `id`)不能混,见 §1.6。
13. **审核类接口的状态值必须是整数**,后端强转不做保护,传字符串会 500。
14. **房东"取消认证"发 3(=已拒绝)**,不是 0。既有语义,照抄。
15. **订单 `orderStatus` 1/2 前端拦截删除**,不发请求,提示「租住中的订单无法删除,请先完结订单」。
16. **反馈"处理"没有二次确认**,且 `reply` 硬编码 `'已处理'`。
17. **轮播图"数字越大越靠前"文案与后端 `sort ASC` 相反**,既有问题,1:1 阶段不改。
18. **改密码成功后 1500ms 强制登出**,且密码只存在 JVM 内存里,后端重启后又变回 `123456`。
19. **房源详情不发请求**,靠列表行数据,所以详情里没有 `pics`、没有房东联系方式(`/house/detail/{houseId}` 那套 18 字段响应本次不用)。
20. **概览的三个接口每次增删改都全量重拉**,数据量大时会慢。1:1 阶段保持,但新前端把「重载」收拢成一个函数,后续好优化。
21. **后端零改动**:任何"顺手修一下后端"的冲动都要先问,因为 `miniapp/` 也在吃同一套接口。
